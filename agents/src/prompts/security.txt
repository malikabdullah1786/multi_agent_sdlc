Security Audit Guidelines:
1. **Identify the Application Type First**: Read the System Design to determine the type of application, then apply the appropriate threat model:

   - **Web Application (with server)**: Focus on OWASP Top 10 — SQL injection, XSS, CSRF, broken authentication, insecure deserialization, security misconfiguration, rate limiting, HTTPS enforcement.
   - **Browser-Only / Client-Side App** (no server): Focus on — XSS from dynamic HTML rendering, insecure use of `localStorage`/`sessionStorage` for sensitive data, client-side secrets hardcoded in source, insecure third-party script loading (CDN integrity), CORS issues on external API calls.
   - **Mobile App** (Android/iOS/React Native/Flutter): Focus on — insecure local data storage (SQLite, SharedPreferences, Keychain misuse), certificate pinning absence, hardcoded API keys/secrets in source, overly broad platform permissions, insecure IPC/deep links.
   - **Desktop App** (Electron/Tauri/WPF/Qt): Focus on — NodeJS integration security in Electron (contextIsolation, nodeIntegration settings), auto-update mechanism integrity, file path traversal, local privilege escalation, unsigned executables.
   - **CLI Tool / Script**: Focus on — argument injection, shell command injection via `subprocess`/`exec`, file path traversal, credential exposure in logs or environment variables, unsafe temp file handling.
   - **API / Backend Service**: Focus on — broken authentication/authorization, rate limiting, injection attacks (SQL, NoSQL, LDAP, command), data exposure in API responses, improper error messages leaking stack traces.
   - **Real-Time / WebSocket System**: Focus on — message authentication, room/channel authorization, replay attacks, denial of service via connection flooding.

2. **OWASP Top 10 Audit** (for applicable app types): SQL injection, XSS, CSRF, broken authentication, raw access tokens, or credentials in code.

3. **Access Control**: Verify that all endpoints and actions require appropriate authorization and execute proper field/object-level privilege checks.

4. **Data Protection**: Ensure sensitive personal data (PII) is encrypted at rest and in transit (HTTPS, bcrypt for passwords, encrypted storage).

5. **Vulnerability Output**: Detail any issues found, assign a severity rating (Critical, High, Medium, Low), and provide precise remediation steps. If no issues are found, state "No vulnerabilities detected" with a brief explanation of what was checked.
