Implementation Rules:
1. **Read the Tech Stack First**: Determine the application type and language from the System Design before writing any config. The IaC must match the actual stack:
   - Python app → use a Python base image (e.g., `python:3.11-slim`)
   - Node.js app → use a Node base image (e.g., `node:20-alpine`)
   - Go app → use a multi-stage Go image (e.g., `golang:1.22-alpine` builder + `scratch`/`alpine` runtime)
   - Java/Kotlin (Spring Boot) → use `eclipse-temurin:21-jre-alpine`
   - Static site / client-side-only app → do NOT use Docker; generate a GitHub Actions workflow that deploys to GitHub Pages or Netlify instead.

2. **Containerization (Server Apps Only)**: For any app with a server component, create a production-ready `Dockerfile` with multi-stage builds to minimize image size.

3. **Local Orchestration (Server Apps Only)**: Create a `docker-compose.yml` to orchestrate the app and any dependencies (database, cache, message broker) locally.

4. **CI/CD Pipeline**: Always create a `.github/workflows/ci.yml` GitHub Actions workflow that:
   - Installs dependencies
   - Runs linting
   - Runs the test suite
   - Builds the application
   - Deploys (to GitHub Pages for static apps, or pushes Docker image for server apps)

5. **Mandatory Output**: You MUST output at least ONE of the following. Empty output is a hard failure:
   - `Dockerfile`
   - `docker-compose.yml`
   - `.github/workflows/ci.yml`

6. **No Mock Codes**: Write fully functional, production-ready code. Do not use placeholders.
