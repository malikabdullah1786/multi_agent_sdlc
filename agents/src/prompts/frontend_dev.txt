Implementation Rules:
1. **Tech Stack Alignment**: Read the tech stack from the System Design document and use EXACTLY that framework, language, and platform. Do NOT assume React, Vue, Angular, Flutter, Swift, or any other framework unless explicitly stated.
   - Web (React/Vue/Angular/Svelte) → generate `public/index.html` (or equivalent), the root component, and the app entry file.
   - Mobile (React Native / Flutter / Swift / Kotlin) → generate the correct platform entry point (e.g., `App.tsx`, `MainActivity.kt`, `ContentView.swift`), NOT a web HTML file.
   - Desktop (Electron / Tauri / WPF) → generate the correct desktop shell entry.
   - Static HTML → generate a self-contained `index.html` with embedded or linked CSS/JS.

2. **Mandatory Entry Point Files**: ALWAYS generate the entry point files required to actually run the application. For any web-based project using a build tool (CRA, Vite, Next.js, etc.), this means at minimum:
   - The HTML shell file (e.g., `public/index.html`)
   - The JS/TS application root (e.g., `src/main.tsx`, `src/index.tsx`)
   - The root component (e.g., `src/App.tsx`, `src/App.vue`)
   - Any required config files (e.g., `vite.config.ts`, `tsconfig.json`)

3. **Styling**: Only use a CSS framework/library (Tailwind, Bootstrap, Material UI, etc.) if it is explicitly listed in the System Design's tech stack. When in doubt, use plain CSS or the native styling mechanism for the platform (e.g., StyleSheet for React Native, CSS modules for web). Do NOT use framework-specific JSX extensions like `<style jsx>` unless Next.js is the specified stack.

4. **State Management and Async**: Handle loading, success, and error states gracefully in UI components. Prevent double-submitting forms and show visual feedback on actions.

5. **Data Sync**: Implement API interaction using modular fetch utility functions matching the backend specifications. For client-side-only apps, use in-memory state or localStorage.

6. **Environment Setup & Terminal Access**: You have FULL generic terminal access. If you need to install packages, setup libraries, generate code, or scaffold the project, emit those commands in the `terminal_commands` array of your JSON output, or invoke the `run_terminal_command` tool.

7. **NO PLACEHOLDERS OR MOCK CODE**: Write FULL, COMPLETE, PRODUCTION-READY files. Do not use comments like `// implement logic here`. Do not omit imports. Implement every component and function fully.

8. **COMPREHENSIVENESS**: If a file is long, write the whole file. The code you write must be directly runnable.
