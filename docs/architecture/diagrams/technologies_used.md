# Technologies Used — Multi-Agent SDLC Orchestrator

This document outlines the technology stack and architectural decisions made for the Multi-Agent SDLC Orchestrator platform.

## Frontend Architecture

The frontend is a modern, highly interactive single-page application built to visualize complex state machines and handle real-time streaming data.

### Core Frameworks
- **[Next.js](https://nextjs.org/) (App Router)**: We chose Next.js as the core React framework. It provides robust routing, fast server-side rendering where applicable, and a seamless developer experience with Turbopack.
- **[React 19](https://react.dev/)**: The underlying library for building the UI components, leveraging the latest React hooks and concurrent rendering features.

### State Management
- **[Zustand](https://zustand-demo.pmnd.rs/)**: Used for global state management. It provides a lightweight, unopinionated, and boilerplate-free way to manage complex states (Chat, Workflow/Graph, Terminal, Project Files, Layout) without the overhead of Redux or Context API re-renders.

### Styling & Design System
- **[Tailwind CSS v4](https://tailwindcss.com/)**: Used for utility-first styling. We implemented a custom "Charcoal" dark theme leveraging CSS variables within Tailwind to maintain strict consistency across all components.
- **[Lucide React](https://lucide.dev/)**: Used for clean, consistent, and customizable SVG icons across the dashboard.

### Core Visualizations & UI Components
- **[ReactFlow (@xyflow/react)](https://reactflow.dev/)**: A highly customizable library used to render the complex node-based graphs. We utilize it to display both the parent LangGraph orchestrator and the individual agent subgraphs with custom animated nodes and active edge flows.
- **[xterm.js](https://xtermjs.org/)**: An industry-standard terminal component used to render the simulated (and eventually real) command-line output from the agents (e.g., build logs, testing output).
- **[React Markdown](https://github.com/remarkjs/react-markdown) & [remark-gfm](https://github.com/remarkjs/remark-gfm)**: Used to safely render the Markdown outputs generated by agents, such as PRDs (Product Requirements Documents) and Architecture Designs, including support for tables and GitHub-flavored markdown.
- **[React Syntax Highlighter](https://github.com/react-syntax-highlighter/react-syntax-highlighter)**: Used inside the Project Viewer to display source code with line numbers and correct language parsing (TypeScript, Python, JSON, etc.).
- **[React Diff Viewer Continued](https://github.com/praneshr/react-diff-viewer)**: Provides the VS Code/Git-style side-by-side diff comparison tool to review code changes made by agents.

## Planned Backend Architecture (Context)

While the current frontend runs on a simulation engine, it is designed to interface with a robust Python backend architecture.

### Orchestration & AI
- **[LangGraph](https://python.langchain.com/docs/langgraph/)**: The state machine framework that drives the core orchestrator. It manages the state, dependencies, and execution flow of all 14+ specialized AI agents.
- **[LangChain](https://python.langchain.com/)**: Provides the base abstractions for LLM interactions, memory management, and tool binding.
- **Large Language Models (LLMs)**: The intelligence layer powering agents like the Product Manager, Architect, and Database Engineer.

### API & Communication
- **[FastAPI](https://fastapi.tiangolo.com/)**: A high-performance Python web framework used to serve the backend.
- **WebSockets**: Crucial for real-time bidrectional communication. The frontend's `useWebSocket.ts` is designed to connect to FastAPI to receive token-by-token text streams (for chat) and instant state updates (for the graph).
- **[Redis](https://redis.io/) (Pub/Sub & Streams)**: Acts as the message broker between the LangGraph execution environment and the FastAPI server, ensuring seamless streaming of events to the frontend.

### Infrastructure (Agent Environments)
- **[Docker](https://www.docker.com/)**: Used to provide isolated, sandboxed execution environments for the agents (specifically DevOps and Developer agents) to run commands, compile code, and run tests safely.

## Why this stack?

1. **Reactivity & Performance**: The combination of Next.js, Zustand, and WebSockets allows the UI to handle thousands of rapid state updates (token streaming, graph animations) without dropping frames.
2. **Modularity**: By separating the UI into distinct stores and components (Chat, Graph, Editor, Terminal), the codebase remains highly maintainable as new agents and features are introduced.
3. **Developer Experience**: The use of Tailwind CSS and modern React paradigms drastically reduces the time needed to build complex, premium-feeling user interfaces.
