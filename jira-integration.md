# Jira Integration Documentation

## Architecture Overview
The Jira integration within the multi-agent system uses the official Atlassian `jira` Python SDK to interact with the Jira REST API asynchronously in a synchronous LangGraph Node. This approach was selected over community-built Model Context Protocol (MCP) servers due to its native Python support, stability, and avoidance of background Node.js processes.

## Configuration
The integration is configured via environment variables loaded by `dotenv` in the orchestrator pipeline.
- `JIRA_URL`: The base URL of the Jira instance (e.g., `https://domain.atlassian.net`).
- `JIRA_USER_EMAIL`: The Atlassian account email.
- `JIRA_API_TOKEN`: The API token generated from the Atlassian security profile.
- `JIRA_PROJECT_KEY`: The default Jira Project key (e.g., `KAN`) where issues are generated.

## LangGraph Node Implementations

### 1. `create_jira_epic_node`
**Purpose:** Acts as the parent container for the AI-generated workload.
- Extracts `JIRA_PROJECT_KEY` from the environment.
- Formats the project name (e.g., `proj-test` -> `Proj Test`) to serve as the Epic summary.
- Takes the PRD (`state.prd`) and truncates it to 5,000 characters to adhere to Jira's maximum field size limitations.
- Invokes the `@tool` wrapped `create_jira_epic` function.

### 2. `create_jira_tickets_node`
**Purpose:** Iterates through the `workflow_tasks` generated by the Task Breakdown Agent and maps them to child Jira issues.
- Takes the `jira_epic_key` generated in the previous step to establish the parent-child hierarchy.
- Invokes the `create_jira_tickets` tool, passing the list of `workflow_tasks` containing the title, description, assignee role, and target files.

## SDK Tool Implementations
Located in `agents/src/agents/product_manager/tools/__init__.py`.

### `create_jira_epic`
- Initializes the `JIRA` client using `basic_auth`.
- Constructs the issue payload with `issuetype: {'name': 'Epic'}`.
- Calls `jira.create_issue()`.
- Returns the newly created Epic Key and a fully qualified Browse URL.

### `create_jira_tickets`
- Iterates over the `tasks` array.
- Constructs the issue payload with `issuetype: {'name': 'Task'}`.
- Maps the task role to the summary: `[<assignee_role>] <task_title>`.
- Appends `target_files` to the description.
- Links the task to the parent Epic using standard Jira Cloud hierarchy: `'parent': {'key': epic_key}`.

#### Fault Tolerance & Fallback Hierarchy Mapping
Jira instances (Data Center vs. Cloud vs. Next-Gen projects) handle parent links differently. Some use the `'parent'` key, while others use specific custom fields (e.g., `customfield_10014` for Epic Link). 
To prevent workflow failure, the tool implements a nested `try-except` fallback:
1. Attempts to create the issue with `'parent': {'key': epic_key}`.
2. If the API rejects the hierarchy mapping, it strips the `'parent'` key, appends `"(Intended Parent Epic: {epic_key})"` to the ticket description, and re-submits the payload.
